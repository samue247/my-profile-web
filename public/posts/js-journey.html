My Journey Learning JavaScript: Mistakes, Breakthroughs and Lessons

From confusing callbacks to finally understanding async/await — an honest account of learning JavaScript as a self-driven computer science student in Nigeria.

By WamiriX · Computing Science, Federal University of Agriculture Abeokuta

Three years ago, around 2023, I knew exactly two things about building websites: HTML and CSS. And I will be honest with you, I only liked one of them. HTML made sense to me. You put things in boxes and the boxes behaved. CSS, on the other hand, asked me to be creative with design, and creativity with colours and spacing has never been my strongest muscle.

So when I discovered that JavaScript could make a page actually do things, respond, calculate, change, remember, I was hooked. What I did not know was how often it would also make me want to close my laptop and go and stare at a wall.

This is the story of that journey: the learning, the bugs that humbled me, and the one conversation that made things click. If you are a self-driven student somewhere in Nigeria wondering whether you are the only one struggling, you are not.

How I actually learned

I started with YouTube, like most of us. Then I moved to online documentation, which felt like reading a foreign language at first and then, slowly, like a map. Along the way I had real people in my corner too: mentors who sat with me physically, looked at my screen and said, “No, that is not what the code is doing.”

Mostly, though, it was commitment and discipline. JavaScript is frustrating, and motivation does not survive frustration. Showing up on the days you do not feel like it does. Projects were where everything finally stuck, because a tutorial can lie to you but your own broken app cannot.

The bug reports I wish I had filed

Every JavaScript learner collects a private museum of mistakes. Here are five from mine, filed properly, as if I were reporting them to myself.

The Two Equals Signs That LiedSeverity: embarrassing
"5" == 5    // true  (JavaScript quietly converted the type)
"5" === 5   // false (different types, different things)
Symptom
My if-statements passed when they had no business passing.
Cause
Loose equality converts types behind your back.
Fix
Use === by default and make type conversion something I choose, not something that happens to me.
undefined Is EverywhereSeverity: daily
const user = {};
console.log(user.name);        // undefined
console.log(user.name.first);  // TypeError!
Symptom
A variable I was sure had a value kept answering “undefined”, and then crashing the whole script.
Cause
I was reading data before it existed, or from the wrong place.
Fix
console.log everything, then check the shape of the data before touching it.
The Loop That Ate My LaptopSeverity: fan noise
let i = 0;
while (i < 10) {
  console.log(i);
  // forgot i++ ... forever
}
Symptom
Browser tab frozen, laptop fan sounding like a small aircraft.
Cause
The loop condition could never become false.
Fix
Always ask: what changes each round so this loop can end?
var, Scope and the Three 3sSeverity: confusing
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// prints 3, 3, 3 (not 0, 1, 2)

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// prints 0, 1, 2
Symptom
Every callback saw the same number.
Cause
var shares one variable across the whole loop; let gives each round its own.
Fix
Stop using var. Learn scope properly instead of guessing.
The Missing awaitSeverity: sneaky
const data = fetchUsers();
console.log(data);   // Promise { <pending> }

const data = await fetchUsers();
console.log(data);   // the actual users
Symptom
I was staring at Promise { <pending> } when I wanted my data.
Cause
The function returned a promise and I never waited for it.
Fix
await it, inside an async function.

The callback pyramid of doom

Then came callbacks. On paper the idea is simple: pass a function in, and it runs later. In practice, my code slowly drifted to the right of the screen until it looked like a staircase to nowhere. Every step depended on the one before it, every error needed its own handling, and I could no longer say with confidence what ran first.

The breakthrough

The first real click did not come from a video or a docs page. It came from a mentor, my CTO. Watching someone experienced slow down and trace what runs, and when, did more for me in one sitting than weeks of copying examples. Async code stopped being magic and became a question I could answer: what am I waiting for, and what happens after it arrives?

Async code stopped being magic and became a question I could answer.

Once that mental model landed, async/await felt like someone had finally switched the lights on. Same logic as the pyramid, but written the way I think:

// before: the pyramid
getUser(id, (user) => {
  getPosts(user, (posts) => {
    render(posts);
  });
});

// after: reads top to bottom
async function showPosts(id) {
  const user  = await getUser(id);
  const posts = await getPosts(user);
  render(posts);
}

What I would tell my 2023 self

  • Read the error message first. It is usually telling you exactly where to look.
  • Build things, even ugly things. Projects teach what tutorials cannot.
  • Find a mentor. One person tracing your code with you can save weeks.
  • Be consistent, not heroic. Small daily practice beats occasional all-nighters.
  • Make friends with console.log. And later, with the debugger.
  • The frustration means you are learning. It is not evidence that you are not cut out for this.

Still learning, still debugging

I am not done. New bugs arrive every week, and honestly I have made peace with that. If you are learning JavaScript right now, from a hostel room at FUNAAB or anywhere else, keep going. Your future self will laugh at today’s bugs the way I laugh at mine.
